### 好友结缘：每位新旅伴都有直接价值

- 计数对象是双方在游戏内完成结缘的不同Steam好友，不是Steam好友列表总人数，也不是发送邀请次数。双方在线确认并交换身份后，各获得一次好友专属蛋；同一SteamID组合只记录一次，重复邀请、删好友再加不重置奖励。无游戏访问权限的朋友先由玩家主动分享商店页，进入游戏后再结缘；不自动群发消息。
- 持续收益沿用已有规则：**每位结缘好友每24小时有30%概率贡献一枚好友蛋**，各好友独立结算。10位好友平均约3枚/天、30位平均约9枚/天，是长期数学期望，不是每日保底。沿用已有54种好友专属形态及品质概率，不通过好友数量直接叠加战斗属性。
- 结缘后不要求好友同时在线。周期进度与领取结果保存在自己的档案；联网取得有效可信时间后结算离线积累，计时失败暂缓领取。PC时间适配优先使用Steam时间，继续遵守既有TrustedClock的失败与已结算周期规则，不另用可修改的系统钟补发奖励。
- 旅伴页用伙伴形象、蛋和已结缘好友列表展示收益；显示“每位旅伴30%/天”的真实规则，不宣称确定产量。未获得的专属宠物可以预览，形成邀请动力。好友数里程碑可作为后续外观奖励，本轮不另加一套数值体系。
- SteamID用于身份关联，按账号隔离存档，奖励写入与已领取记录一起保存。现有拜访码不能冒充Steam结缘身份。此方案确认“朋友实际进入并参与游戏”，不证明购买来源、永久付费许可或邀请转化归因；不使用需要安全服务器的CheckAppOwnership，也不在客户端放发行商密钥。

### 多人副本：骰子决策、仇恨与团队配合

- 建议支持2–4人好友房，每人带3只已有宠物，场上控制1只，另2只候补。队友同时出场，Boss血量和机制按开局人数配置，战斗中不靠临时增减人数改变难度。守护、输出、支援是宠物和技能搭配形成的职责，不要求重新创建职业。多人副本另设资源与结算，不扣改主线体力；失败不丢失已有宠物。
- 每轮先展示Boss意图、各人骰子和当前仇恨目标，所有玩家同时选行动与目标，然后准备。全员准备即开始结算；建议普通难度允许房主选择无倒计时，升阶挑战采用统一的30秒准备上限。倒计时结束未选则防御。结算前可撤销自己的准备，结算后不接重复指令；这些时间是本项目起点，不是竞品参数。
- **仇恨**按每个敌人、每位玩家槽位分别记录。有效伤害产生仇恨，有效治疗产生较少仇恨，守护技能强化仇恨；挑衅把自己提至最高并吸引下一次可挑衅的单体攻击。换宠继承本槽仇恨，防止靠切换清空。准备阶段显示预测目标，玩家行动完成后锁定Boss的实际目标并先给出指向反馈。威胁系数与切换阈值待独立平衡，不声称复用魔兽世界的公式。
- **AOE不受挑衅影响**，提前一轮显示范围和蓄力。示例Boss“熔冠巨龙”（拟新增内容）：撕咬最高仇恨者 → 蓄力全体吐息 → 召唤幼龙。队伍需要安排守护吸引撕咬、支援群体护盾、输出集中处理幼龙；低血量进入强化阶段。骰子决定行动强度与组合取舍，战斗仍以宠物演出为主体。
- 奖励为个人掉落，不抢最后一击。首次通关给一枚对应副本专属蛋；重复通关给固定蛋碎片并有整蛋机会，碎片可选指定蛋，具体兑换数量与概率待平衡。奖励由战斗结算记录驱动，同一场次、同一账号不因重复回调再领；副本蛋池独立于好友蛋池，不能把现有54种好友形态直接改称新副本宠物。
- **联机方式**：Steam Lobby管理房间和邀请，SteamNetworkingMessages传可靠消息；一位玩家的电脑担任房主，计算回合结果。参与者使用相同规则版本、场次编号、动作序号与玩法随机种子，并重演核对结果。这能发现不同步和部分异常，不能阻止修改客户端或多人串通。
- **断线规则**：队员掉线暂停在安全结算点，保留60秒重连窗口；重连按SteamID恢复快照。超时回到组队页，未完成Boss不发奖励。房主掉线首版同样中止本场、保留此前已完成Boss的奖励，可重新建房挑战；不承诺Steam会自动迁移战斗或恢复房主状态。所有中止场次不提交天梯成绩。

### 赛季天梯：展示通关能力与宠物阵容

- 采用用户指定的暗黑3式“赛季＋逐级挑战＋成绩展示”方向，转成回合制指标：**最高通关阶层优先，同阶回合数越少越好，再比较阵亡次数**，完全相同的成绩显示并列，不按网络等待时间判胜负。Boss规则、准备时限和难度随规则版本固定。
