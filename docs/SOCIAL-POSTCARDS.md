# 通信小屋单机版实施记录

用户批准2026-10-21通信小屋优化，随后明确云服务以后开通。本轮沿用Cocos3.8.7与现有全屏模板，不接入账号、远程回执或安装归因，不打包或上传商店。

- [x] 协议与存档：兼容PMV1；PMV2携带昵称、外观、展示技能、3个心愿、回信对象，无战斗数值；12条通信记录，保留结缘与来源。
- [x] 来访：一次共同掷骰即结缘，先保存再动画，可跳过；按心愿推荐回信伙伴；不同来访者不伪装成在线好友。
- [x] 页面：明信片、心愿选择、通信簿、合影与纪念邮票；沿用自己的蛋与品质/地区限制。
- [x] 分享：导出真实立绘明信片PNG与可识别二维码；网页下载/系统分享、安卓系统分享与图片导入，来访码兜底；孵化揭晓增加信封入口，异色、配方外观及共鸣技能进入卡面。
- 历史验证（2026-10-21）：新旧码162形态、错误输入、不转移宠物或战斗属性、存档/结缘幂等、二维码实际图片往返及390/320宽；安卓桥接编译通过。APP/小游戏真机、iOS原生分享未验证，本轮未重打APK。

云端与公开落地页：本轮不部署；无公开服务时二维码包含来访码，通过通信小屋导入。商店尚在审核，不编造可安装链接或安装后自动恢复邀请的承诺。

## 当前操作

营地“来信”进入收信、寄信、好友三个入口，好友下再进入结缘与合影。明信片可换伙伴，设置最多12字符昵称、3个系列心愿；技能只作展示，最多6个。收到图片时选择“导入明信片图片”；也可粘贴PMV1/PMV2来访码。自己的码拒绝导入。

“一起掷骰”立即提交结缘与合影，再播放首轮8秒、后续2秒的展示，可点击查看合影跳过。两个骰子各1～6，只决定三种纪念印章，不影响蛋品质或战斗数值。相同来访者的同一系列只保留一条合影；最近12条展示在通信簿，旧合影移出不会删除已解锁的结缘系列。回信优先选择自己拥有且满足对方心愿的伙伴，否则当前出战或第一只伙伴。

结缘使用自己的蛋；品质固定，高品质蛋仍要求解锁目标地图，本地交配蛋保留自己的遗传属性与技能。好友宠物不直接加入收藏。结缘蛋保存来源昵称，孵出后伙伴技能详情显示来源。旧三次互动记录兼容保留，新界面只需一次掷骰。

## 分享实现与边界

- PNG为720×960，用现有真实宠物图、当前语言标题、品质/属性、技能亮点、心愿和二维码。Cocos RenderTexture截图时提高文字栅格分辨率，保持缩略图与导出一致。
- 网页支持浏览器系统文件分享时打开分享面板，否则下载PNG；图片导入在本机解码，不上传到服务器。来访码复制失败时显示可手动复制的输入框。
- 安卓通过FileProvider仅共享cache/pm-share路径的图片；系统文件选择器导入，系统创建文档入口保存，不索取全图库或存储权限。二维码由ZXing3.5.3本机解析。dicepet://postcard?code=…可交给已安装应用，未安装不提供跳转承诺。
- 小游戏保留现有平台shareAppMessage/相册保存与剪贴板适配，图片导入不可用时使用来访码；仍待平台验证。iOS原生图片分享尚未接入。
- 图片二维码只包含离线码，不是下载网址。没有远程自动回执、在线状态、真实邀请人数或账号；离线回信可由发码者手动导入；打开分享面板不视为成功送达。码带校验和用于发现复制错误，不作身份认证。
- JS二维码：qrcode-generator1.4.4（MIT）、jsQR1.4.0（Apache2.0），源码与许可证在assets/scripts/vendor；安装清单tools/social-deps，运行不依赖网络库下载。

检查入口：`node tools/workflow.cjs --scope postcards`；截图与导出样张在checks/postcard-*.png。测试使用独立存档，未覆盖用户进度。

## 好友专属蛋与定时赠礼（现行）

扫码者导入非本人来信后获得一枚好友蛋，并生成回信；原发码者导入回信后领取一枚。同一好友配对各限一次，不伪装为云端通知。朋友信息为离线快照。每好友每24小时按30%概率赠一枚蛋，可信校时成功后补算周期（单次最多1000周期），结果保存不重抽。无服务器时校验码不构成防伪身份认证。

好友蛋只出18属性各R/SR/SSR的54个专属形态，品质70%/25%/5%；普通地图蛋不能获得这些系列。好友赠蛋与原自有蛋结缘为两个不同来源；访客本体不会直接加入队伍。
