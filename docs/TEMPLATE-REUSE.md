# 用 PM 模板制作新项目

此模板已具备宠物收集＋随机战斗＋离线成长的浏览器原型基础。复用应从现有数据和页面开始；这份指南是后续执行参考，本轮没有复制新项目或新增功能。

## 最短落地路径

1. **先确定范围。** 保留哪几条循环、几张地图、几个系列；区分纯换主题与更改规则。优先做一张地图、少量系列的完整可测试流程，再铺内容。
2. **新目录复制必要文件。** 保留`assets/`及所有`.meta`、`settings/`、`package.json`、`tsconfig.json`、构建配置、试玩脚本、工作流工具、适用检查和docs。保留需要继续生产的`art-source/`。`library/temp/build`是可重建缓存/产物，旧截图日志不属于产品资源；不要在原PM目录清理或试验迁移。
3. **独立身份与入口。** 修改项目名/项目UUID、保存键与所有备份前缀、IndexedDB数据库/仓库/键和音频偏好键、试玩端口/URL、构建日志路径、社交码协议前缀。检查硬编码的`D:/game/PM`、8780、旧版本文案。保留复制资产的meta引用关系；若场景UUID变化同步构建入口。
4. **接入最小内容。** 替换PETS、FORM_NAMES、PET_SKILLS、地图池和蛋规则，再接图与裁切。当前MAPS/eggRates/encounterRarity不是任意地图数量的全配置框架，不能只在MAPS末尾加一行就宣称支持额外地图。
5. **复用页面结构。** 营地、战斗四键、点数组二选一、图鉴拖队、等待/领取、帮助使用现有组件。无关功能可通过明确入口裁剪，勿留下点开报错的半残页面。
6. **独立存档验证和试玩。** 从空档启动→首战→奖励→寻蛋→孵化→编队；保留的交配/来访分别验证。对原项目升级则增加旧档迁移检查；不同新项目不误读PM存档。
7. **交付并更新文档。** 运行适用工作流、看相关截图、给用户单一试玩URL；重生成数据表，更新交接卡与待验收项。用户决定下一轮。

## 复用与替换清单

| 能力 | 通常可直接复用 | 新主题需改动 |
|---|---|---|
| 战斗循环 | 状态机、回合、药水、防御、单次技能框架 | 名称、点数、技能条件、奖励曲线 |
| 收藏/编队 | UID、重复个体、拖拽三槽、分页 | 图鉴字段、队伍限制、角色图 |
| 孵化/交配 | 可信时间、双槽、领取幂等、遗传 | 时间、品质池、消耗与继承项 |
| 离线社交 | 访客快照、互动、结缘定向 | 协议版本/系列编号/地图限制 |
| 表现 | UI容器、输入反馈、战斗tween、脚底对齐 | 配色、场景、宠物、图标、尺度 |
| 工程 | 模型/显示分离、局部刷新、相关测试选择 | 本机工具路径、保存键、端口、平台构建 |

自动路由维护在 `tools/workflow.config.json` 的 `moduleRoutes`，只作用于显式传入的文件。例如：

```powershell
node tools/workflow.cjs --scope auto --file assets/scripts/LocalizedLogoArt.ts --plan
node tools/workflow.cjs --scope app-battle,logos
```

APP与小游戏共享数值和存档；增强姿态、场景和粒子按表现能力启用。单个效果被批准复用时，不连带开启整个APP资源包。品牌标题使用独立语言图片，普通按钮/数值仍用翻译系统；首屏只载入当前语言LOGO。

## 新模块接入的最小闭环

1. 按功能选scope，保留既有服务边界；PMModel/PMGame仍为大型文件，不宣称已经完全插件化，也不在复盘时大拆分。
2. 新字段同时覆盖旧档恢复、随机结果持久化与重复领取；临时效果/展示信息不得混入永久基因。
3. 新文案写入源TSV再生成，动态计时也使用翻译。测试必须确认实际语言和页面文字；只设置偏好但被初始化覆盖，不算外语测试通过。
4. 新入口登记workflow scope与精确文件路由，再生成release清单。规则、运行页面、平台桥分别验证。新增图片共享模块必须测试真实导出图片再导入，不能只测编码函数。
5. 新音频统一按manifest路由；旧资源退役时同步移除能重建旧文件的工具路径，保留仍在使用的母版和许可证。
6. 画面验证按真实内容区划分，长名称、小屏、多语言使用实际节点边界及截图。记录结果后交用户测试；不顺带打包。

## 文档同步方法

修改模型/资源后在项目根运行：

```powershell
node tools/export-design-data.cjs
node tools/export-design-data.cjs --check
```

生成`docs/generated/design-data.json`、`TABLES.md`、`ASSET-INVENTORY.md`；直接使用模型导出函数，不维护第二套HP/敌攻公式。编译器路径默认读取workflow.config，可用环境变量`PM_DOC_TYPESCRIPT`指定TypeScript模块文件。换电脑先更新工作流工具路径。

生成器验证系列/地图归属、概率总和、形态双角度矩形、脚底范围、文件存在并记录源码SHA-256。它不是自动改代码、AI调参或平台发布工具。规则文字仍由本次修改者核对，不应认为自动表刷新即整个策划文档已同步。

每次需求可直接沿用以下简短记录，填完只执行已确认范围：

| 项目 | 填写内容 |
|---|---|
| 目标 | 玩家将看到/能做的具体变化 |
| 保持 | 本次必须保持的现有规则与存档 |
| 数据 | 配置入口、新旧数值、概率、触发条件 |
| 页面 | 复用哪个模板，选择/空/等待/完成/不足状态 |
| 兼容 | 对旧档、旧资源、来访码的影响 |
| 验收 | 最少必要场景、试玩入口、需要用户决定的效果 |

不要把模板的所有栏扩展成额外开发任务；与本次无关的栏写“不涉及”即可。

## 适合复用的边界

批量宠物扩展先维护生产名册（稳定ID、属性、形态、轮廓、技能机制、视图），只定向处理新增图集；实际检查alpha、裁框与脚底，保留原画和旧UUID。同步翻译源与生成词典，检查窄屏长文字和阿拉伯/印度文字连接，不能只核对key数量。

平衡工具 `tools/simulate-balance.cjs` 调用真实单宠开局和养成接口，避免旧测试工厂额外发宠；报告必须说明种子、策略、失败截尾和模拟时间。当前脚本针对PM的12图和队伍规则，复用到新游戏先替换这些假设。见[数值模拟](BALANCE-SIMULATION.md)。

已同步可安装的[开发SKILL](../tools/skills/cocos-miniapp-game-dev/SKILL.md)和[批量内容与平衡经验](../tools/skills/cocos-miniapp-game-dev/references/catalog-and-balance.md)。按需读取，不给普通小修改增加全量测试、多代理或额外复盘。

当前为Cocos的二维图像表现；适合低操作负担、回合战斗、收集挂机原型。开放世界、实时多人、3D实时海面不属于这套实现。微信/抖音发布前需要按当时平台要求完成接入与真机测试；当前仓库没有“复制即上线”的保证。

已移除过时初始化/补丁脚本。复制最终源码与当前文档；有资产变更才调用相关生产脚本，不重放历史制作过程。
