# 美术资源与 UI 接入规范

当前实现基线：2026-10-20。全屏页面参数沿用 [UI-PATTERNS](UI-PATTERNS.md)，资源实测清单见 [ASSET-INVENTORY](generated/ASSET-INVENTORY.md)，每个形态的前后视图矩形与脚底坐标见 [design-data.json](generated/design-data.json)。

## 视觉方向与资源拆分

原创宠物收集冒险；清晰轮廓、明亮色块、较少细碎纹理。普通体态相对圆润，进阶形态通过角、翼、甲、尾、鬃和体量变化形成家族关系。形态外观与实际关卡类别是不同维度，不能凭图片推断关卡数值。

资源分为无字场景底图、透明宠物图、独立图标、程序绘制的卡片/血条/蛋以及独立地台图。文字与动态数字由引擎绘制，不烘入整张界面图，方便换主题、换语言、更新数值。

| 战斗图标 | `attack-die-a / heal-potion / power-potion / guard-shield / loot-chest / refresh-enemy / battle-start` | 同套立体卡通风格，数字另绘制 |
| 生成来源 | `art-source/type-roster-v1/`、`art-source/evolution-v1/`、`art-source/egg-hunt-v1/` | 保留提示词、清单与原图；可用范围依实际文件，不假设每张都有完整来源 |

我方战斗图：左下近景、背面三分之四、面向右上。敌方：右上远景、正面三分之四、面向左下。收藏图使用正面。不要通过把同一侧面图水平翻转假装前后两个视角；fox旧R卡片的水平翻转是特定资源兼容。

矩形 `[x,y,w,h]` 以源图左上为原点，单位像素。脚底 `feet=[u,v]` 是**裁切后**画面中接地点的归一化坐标，v向下。图片等比fit进逻辑框；`groundPet` 实际将UI锚点设为 `(u,0.5)`，节点x放在地台目标x，节点y放在 `地台y+(v-0.5)×显示高H`，令脚底接地。等效的图心横向偏移是 `(0.5-u)×显示宽W`。尾巴和耳朵外接框不能代替脚底。

初始三只脚底在 `PMGame.petFeet` 有覆盖值，导出数据已合并该覆盖；调图时必须同时检查覆盖与BattleArt，应同步当前Art映射与自动数据。`groundX` 还会按屏幕边缘约束可用横坐标。

R源图并非全部相同像素尺寸；历史15张新双视图1536×1024，旧3张与进化图有各自实际尺寸。**现状统一的是逻辑显示、透明背景、双角度、矩形与接地点，不是把所有原图强制拉成512×512。** 所有实际像素和文件大小由清单读取，不手抄。

## 当前场景与封面资源

第7～9图复用第4～6图主题背景与地台；已有六地区背景由 PMGame.loadRegionArt 按所选地图加载；第二至六图使用 region-<地图编号>-battle/nest-v1。地台来自 region-pads-v1 图集，裁切映射在 RegionPads。营地由 HomeScenery 按手机本地时段选用六张底图；这是装饰时间，不用于体力或孵化结算。环境动态有数量上限并尊重减少动画偏好。封面使用 login-cover-v2、login-title-v3、login-button-v4，第三主角使用 trainer-medic-v2；完整现用文件以自动资源清单为准。

## 当前战斗尺度

`petScale` 来自PETS.rank：normal=0.80、elite=1.15、boss=1.50，这是旧系列美术体型，不是当前地图关卡身份。

战斗底部区246高；可用场景高S=屏高−246，基础尺寸B=min(230,S×0.38)。我方框尺寸=`B×1.2×min(1.15,petScale)×0.9`，敌方框尺寸=`B×0.65×0.8×petScale×1.1`。脚底分别位于屏幕顶部向下0.92S/0.62S，横向偏好−92/+82并经过边界修正。敌人地台在原20%扩幅基础上再扩大15%，不绑定成同一节点整体缩放。大小按完整角色可见轮廓与脚底检查，不能只看PNG宽高。

敌人HUD独立绘制字体和血条，血条只缩放填充，不缩放整条文字。当前HUD挂敌人节点上，角色呼吸也会轻微带动HUD；大幅缩放角色时应复核HUD是否变形。

## UI 页面复用

- 逻辑分辨率390×844，FIXED_WIDTH；高度随设备变化。重点检查390×844、320×568，不能把全页压扁来挤进小屏。
- 顶部战斗地图标题居中白字描边，无大底板；探险右上为回家图标。敌方数据贴近敌人；选敌的敌我姓名/点数组共用 `encounterNameAttack`。
- 战斗四键为2×2：治疗绿、力量红、防御蓝、攻击橙。每个药水图标右下数量，公式右侧，禁用整键灰、已用勾；伤害数值与随机攻击图标独立。
- 胜利：单项领取；攻击/治疗数组新旧两张比较卡。UI文案不得宣称BOSS同样经过奖励恢复。
- 伙伴/孵化/蛋袋/交配/来信共用全屏页、红标题栏、左返回、浅底白卡、底部操作；概率与复杂说明收进帮助。关键永久消耗必须可见。
- 可按按钮轻呼吸描边、按下缩至0.94、释放回弹；触发间隔180ms并有动画忙碌锁。刷新局部数据时保留无关节点，避免按钮反复闪烁。
- 伙伴拖拽有浮动图、目标槽提示，松手交换；取消恢复原图。未拥有图鉴卡和战斗中队伍不允许拖换。

现有动画通过tween完成呼吸、攻击冲刺/回位、受击闪色与抖动、火花、浮字、血条变化、胜利跳跃、蛋揭晓；没有逐宠物骨骼动画系统。换皮应保留主轮廓和动作辨识，先复用这些反馈。

## 新增或替换宠物资源步骤

1. 先定系列ID、三形态名称、属性、角色体型和两角度关系；检查是否已有可复用资源。
2. 输出透明背景原图；同时保留原图和提示词。沿用双/四视图时保证各角色互不相交，四肢不裁断。
3. 接入resources并保留已有`.meta`/UUID。记录裁切矩形与脚底；保持等比，避免将透明边当身体。
4. 更新对应Art表与PMGame加载映射；只更新模型名称不会自动出现新图片。初始三只还有卡片与脚底特例。
5. 用导出脚本检查矩形在图内、资源存在、162形态双角度完整；然后按当前任务选UI/战斗检查，实际看近远比例、脚底与小屏。

历史初始化/补丁脚本已移除。register-evolution-art、register-region-art和index-battle-art仅在接入对应资产时使用，先核对输入与写入目标，不作为构建前置步骤。

## 性能与平台边界

启动仅加载封面、标题、按钮3张美术纹理；其余由PMArt按当前页面/可见分页请求。同图集并发请求合并，节点存活期间保持引用；未使用纹理闲置4秒或缓存超过32MiB时优先回收。32MiB是闲置缓存回收触发值，不是包含当前页与滑动相邻页的绝对内存上限。裁切帧仍引用整张图集，释放时销毁动态帧并通过Cocos引用计数释放纹理及依赖。

运行PNG已缩小并作无损PNG编码优化，完整原图在`art-source/runtime-masters-v1/`，不进入游戏构建。`tools/prepare-runtime-art.py`从原图重复生成运行图，保留.meta UUID。裁切坐标仍基于原图，PMArt利用ArtSourceSizes按实际纹理尺寸换算；自动表另给runtimeRect。更换已有美术时先更新对应master与裁切数据，再运行此脚本，不可只覆盖运行图后再次用旧master生成。

资源表的PNG文件大小、RGBA估算与构建包大小、平台主包/分包大小不同。此次未接平台分包、远程资源或GPU专用压缩格式；手机平台预算仍需真机验证。此次没有重新绘制宠物；清晰度已在390/320宽实际界面检查，详见[资源优化结果](RESOURCE-OPTIMIZATION.md)。动态Label仍使用CacheMode.NONE。
