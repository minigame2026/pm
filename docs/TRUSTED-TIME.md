# 可信时间与离线结算

2026-10-19。用户选择：不自建服务器，允许联网取得可信时间；保留离线收益，校时失败暂缓结算。

- 浏览器启动、从后台返回必须通过 HTTPS 校时。优先 `timeapi.io`，失败尝试 `worldtimeapi.org`，每个请求超时5秒；不发送玩家存档、宠物或账号资料。
- 获得 UTC 时间后，用 `performance.now()` 累计本次前台经过时间，不再使用手机日历时间计算收益。每5分钟重新校时，失败每30秒重试；锚点最多有效10分钟。切后台立即失效。
- 重新打开时，保存的时间记录只用于拒绝倒退，不能自行恢复可信状态。联网成功后统一结算离线体力、孵化、交配；未校时显示“等待联网”，不领取、加速或开启新的计时任务/探险。
- 已进行的探险可以继续、撤退，收藏可以查看。广告完成但校时失效时，先保存待发奖励，恢复可信时间后只发一次。
- 时钟入口：`TrustedClock.ts`；生产入口在 `PMGame.start` 注入 `PMModel.setTimeProvider`，失效值是 NaN。模型默认时钟仅兼容独立规则测试；新宿主必须在结算前注入可信时钟。不要把 `Date.now()` 再用于奖励或倒计时。
- 旧存档沿用原来的计时截止时间，不清档；无法追溯识别升级前已获得的作弊收益。

边界：这防止常规修改手机时间，不防修改程序、本地存档或伪造客户端。公共时间服务无本项目可保证的可用性；服务不可用时按用户选择暂缓结算。微信/抖音还需要适配平台请求、单调计时和前后台接口，配置合法域名并真机验证；当前验证的是浏览器试玩。

依据：[Unity 时间防作弊方案](https://docs.unity.com/en-us/cloud-code/scripts/use-cases/server-time-anti-cheat)、[MDN performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)。借鉴可信时间锚点和单调计时原理，未引入 Unity 服务。

检查：`checks/trusted-clock.test.cjs` 覆盖拨快/拨慢、单调计时、重启、离线拒绝结算、回退拒绝、有效期；`checks/trusted-time-runtime.cjs` 覆盖真实 HTTPS/CORS、断网重开、恢复网络后结算孵化与交配，以及结算回营地、交配排除出战宠物。截图在 `checks/`。未操作用户试玩存档。
