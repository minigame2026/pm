# PM 页面模板标准

依据：用户指定“伙伴”的全屏格式为统一方向。孵化屋、蛋袋、交配、来信已按此实现，当前具体外观仍待用户试玩评价；不要写成已验收。

## 页面路由
| 类型 | 复用位置（PMGame.ts） | 应放的内容 |
|---|---|---|
| 常驻功能全屏页 | `fullPage`、`sectionHeader`、`pageBounds` | 标题、返回、内容区、底部主要操作 |
| 伙伴/蛋/系列选择 | `partnersUI`、`eggShelf`、`bondsUI` | 卡片、选中态、分页、选择后的操作 |
| 等待与领取 | `hatchery`、`breedingUI` | 对象、倒计时、可操作状态、领取/加速 |
| 规则帮助或短确认 | `pageHelp`、`overlay` | 当前需要的规则或后果；不承载整个日常功能 |
| 战斗 HUD | 现有战斗布局 | 独立复用战斗模板，不套功能页的全屏结构 |

## 当前项目视觉参数
- 逻辑宽度 390；高度从 `pageBounds` 获取。顶部红色标题栏 88 高，左上返回。
- 页面底色 `#edf4f5`，卡片白色，选中 `#fff1d6`，底部操作区 `#fffdf5`。
- 内容宽通常 354；三列卡片 112 宽、中心间距 120。主要按钮约 350×48；沿用当前相应功能色。
- 倒计时、状态、按钮基于顶部/底部定位；大屏扩展内容区，小屏不能整体压扁字体和图标。
- 子页返回上一级，顶级功能返回进入前的页面；换页不得重置任务、宠物、计时或选择以外的数据。
- 列表分页使用 Cocos `PageView` 横向滑动与吸附，页码保留，去掉左右箭头。`listItem` 标记分页卡片，`pagePager` 统一组织视口；伙伴列表横滑翻页、纵向拖动换队，不能互相触发。空孵化位整块“＋”卡片可点击选蛋。

## 每次实际需要的状态
选择卡片 → 选中态 → 一个主要操作。等待中显示倒计时；资源不足显示灰色与简短原因；可领取时突出按钮；空列表给出一个去向。只实现本次功能需要的状态。

## 文字预算
标题说明所在位置；卡片显示对象、品质和必要数值；按钮用短动词。长概率/遗传规则收进“?”。消耗父母、花费资源等后果必须在行动前可见。数字要带足够语义，避免生造难懂的复合图标。

## 最小检查
先用 `ui` 或 `social` 检查组。查看本次实际生成的 390×844 与 320×568 截图，检查遮挡、挤压、留白和返回路径；截图生成成功不等于视觉通过。不要因为某一次引擎控件故障而扩写整套通用规范。
