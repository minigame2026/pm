# 屏幕适配检查 · 2026-10-20

结论：常见竖屏手机的主要触控流程可用，但当前不能称为所有尺寸适配完成。发现平板伙伴列表遮挡与横屏重叠。此轮记录问题，未改成另一种屏幕布局。

## 已实际运行

- Edge触摸模拟：320×568、375×667、375×812、390×844、393×852、430×932、360×640、360×800、412×915、384×854、390×664、768×1024、820×1180、800×1280；DPR 2/3。
- Windows WebKit：375×667、390×844、768×1024。不是实体iPhone Safari。
- 每种尺寸19个页面：封面、主角、初始伙伴、营地、地图、遭遇、战斗、奖励、寻蛋、胜负、伙伴、图鉴及详情、孵化、蛋袋、交配、来信、设置。共323个页面样本，未捕获JS异常。
- 所有样本的登记按钮矩形均在画布内；这不能替代遮挡检查。实际触摸开始、进入孵化、选蛋、返回、设置开关页面路径通过。
- 17组横竖屏往返均保留游戏状态。画面在横屏仍有重叠，不能把“数据保留”当成“横屏适配通过”。
- 查看了小屏手机、标准手机及平板的代表截图。完整图片与机器结果在 `checks/responsive/`，测试脚本为 `checks/responsive-runtime.cjs`；WebKit以 `PM_BROWSER=webkit` 运行。

## 发现的问题

| 严重性 | 现象与复现 | 原因及后续方向 |
|---|---|---|
| P1 | 768×1024进入伙伴，列表卡片被下方详情覆盖 | FIXED_WIDTH使逻辑高度只有520；固定顶部队伍、列表及底部详情所需空间超过可用高度。后续需为宽屏提供竖屏内容框，或专门压缩/滚动布局。 |
| P1 | 手机旋转横屏后，孵化卡片与标题、底部操作重叠 | 390逻辑宽不变，高度降至约180；网页构建portrait配置没有阻止浏览器横屏。后续建议竖屏游戏框或横屏提示，不扩展成横屏玩法。 |
| 待验证 | 刘海、灵动岛、Home指示条、平台胶囊与系统手势区域 | 构建样式声明了safe-area变量，但游戏UI尚无使用安全区的明确逻辑；普通网页可能由浏览器避让，平台全屏需真机确认。 |

## 验证边界

全部使用独立浏览器存档，没有删除或修改玩家存档。这里验证浏览器布局、事件与旋转，不等于iOS/安卓真机GPU、系统字体、浏览器工具栏动画或微信/抖音SDK认证。

音效/轻滑分页的后续更新单独通过audio、touch及短滑鼠标/触摸检查；没有重新宣称宽屏、横屏问题已经修好。
