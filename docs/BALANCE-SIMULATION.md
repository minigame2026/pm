## 方法与边界

- 使用真实 newJourney → chooseHero → chooseStarter，初始一只；旧fresh工厂不能代表真实开局。
- 调用生产战斗、奖励、孵化、交配及存档接口，无广告、徽章或好友宠物，不直接加HP或解锁地图。
- 只看已展示骰子，不窥探未来随机、不重抽蛋。当前地图连续失败两次回刷上一图，正常孵化并选择三人队伍。
- 受控可信时钟推进正式等待；虚拟时间逐项累计，不能作为真实玩家耗时预测。
- 交配策略只按基础数值和技能数量估值，不穷举协同；交配组不必然比只孵化更快。结果证明存在正常养成路径，不保证每人必通关。
- 模拟不是玩家胜率。首关火系仍比水系难，长期节奏与手感需要真实试玩后局部调整。

## 复用

```powershell
node tools/simulate-balance.cjs first 100
node tools/simulate-balance.cjs campaign 10
node tools/workflow.cjs --scope difficulty-curve
```

原始报告写入被忽略的checks/difficulty-simulation，含模型SHA与假设，不接触玩家存档。汇总见[机器可读结果](generated/balance-simulation.json)。长模拟只在数值任务执行，不加入每次构建。
