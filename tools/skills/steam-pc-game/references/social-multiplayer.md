# 不自建服务器的 Steam 互动

## 可行能力和边界

身份/好友/邀请采用 Steam API，Lobby 管房间，Networking Messages 或项目现有 Steam 网络接口传数据；玩家电脑担任房主。Steam Relay 能协助连接，但不会代写游戏结算，也不会自动迁移房主。

Steam Cloud 不承担实时同步。客户端不能存发行商 Web API 密钥，也不能承诺客户端成绩达到可信服务器的反作弊能力。联机设计完成、模拟通过和多台真实 Steam 客户端通过必须分开。

## 好友带来的收益

计数对象应是实际进入游戏并完成双方确认的不同 Steam 好友，不能只按邀请次数或整个好友列表发奖励。一次性奖励账本和账号存档一起原子保存；重复回调、删加好友或重进房间不能重复领奖。

持续收益若按时间结算，复用项目可信时间；不要用可修改的本机钟直接补发。写出概率或期望值，不能将随机概率说成保底。好友身份与进入游戏不能证明购买来源或永久付费许可，不宣称已经做到购买归因。

邀请和分享由玩家主动操作；战斗中提示可忽略，安全结算/保存后才跳转。不要自动群发好友消息。

## 合作副本

房主结算，消息带场次、回合、动作序号、协议/规则版本。重复消息幂等，执行前重验角色、目标、费用和阶段。玩法 RNG 与表现随机分离；回放自洽只能发现部分异常，不等于防作弊。

Boss 意图、AOE、当前仇恨目标和准备状态优先清楚显示。仇恨按敌人和玩家槽位维护，换宠是否继承必须规则明确；AOE 不被挑衅误转成单体。系数、重连时限和人数缩放是本项目设计参数，不冒称照搬竞品。

断线在安全点暂停或中止，按 SteamID 恢复参与者。首版没有房主迁移时明确中止规则；中止战斗不发通关奖励、不提交天梯。同场奖励记录绑定场次和账号。

## 排行榜

分清单人/人数/规则版本/赛季，排序指标适合回合制，例如阶层优先、再比较回合及阵亡，避免按网络等待时间衡量战斗能力。成绩详情保存当时阵容快照，不显示后来换过的队伍。

Steam 排行榜按用户记录成绩，团队可能在多位成员记录中重复。选择客户端可写的普通榜时不能打开需要可信服务端的写入模式。无自建服务器的赛季榜应定位为荣誉展示，不承诺不可刷榜或远程强制封榜。

真实验收至少两位有应用许可的 Steam 玩家，覆盖邀请、重复操作、断线、房主退出、版本不一致与奖励幂等；四人玩法另验四客户端。
