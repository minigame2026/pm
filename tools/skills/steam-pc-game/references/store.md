# 商店资料、语言及媒体

## 名称和支持语言

游戏内支持语言、商店文案语言、名称本地化、成就语言和字幕/音频是独立配置。游戏有文字翻译不代表支持完整音频；只勾选当前包体实际具备的能力。

先读取游戏现有译名，保留已确认品牌名。Steamworks→通用应用设置→添加本地化名称，保存后再发布应用配置；依据官方说明，此项可覆盖对应语言的商店名称。Steam 可选名称语言少于游戏可实现的语言，不创建后台不存在的语言枚举。

名称保存后要刷新读回，并检查商店对应语言标题。后台出现译名、配置发布成功、商店实际显示是三条独立证据。若预览仍为旧名，只报告已发布/前台未确认，不能把原因直接断言为缓存。页面通过审核后的改名限制另查当前后台及官方说明；需要联系客服时先准备具体名称，不在用户未授权时发工单。

参考：[本地化名称](https://partner.steamgames.com/doc/store/localization#localized_app_names)、[改名限制](https://partner.steamgames.com/doc/store/editing/name)。

## 五语截图经验

- 使用确定版本的实际原生客户端，在游戏里切换语言拍摄。只裁除系统边框/留黑和合理缩小；不可用生成画替代实机，也不添加并不存在的功能。
- 给每个场景稳定编号，如 01-battle、02-camp；给输出添加 Steam 语言代码后缀，降低拖入后错配概率。统一 16:9、1920×1080，并实际检查字形、重叠和关键 UI。
- 将基础截图上传为一行，再向该行添加对应语言变体；不要把五种语言当作二十五张独立轮播。
- 逐行上传并等待服务器保存/页面重载完成。文件选择完成、点击上传或 URL 增加 # 都不是上传成功；刷新后确认每行语言与图像哈希。
- 当前后台会按图片读入完成顺序插入，不能凭文件名假设排序。移动时依据图像内容/哈希；重排后行号会变，必须重读。
- 用户要求替换/删除旧截图时，列明实际旧行，只删旧图，保留新图全部语言。仅新增并排到前面不会移除旧版。
- 旧式拖放组件与页面另一处 React 文件输入可能互不相通；只操作已观察到的目标拖放区。不要因为网页存在 input[type=file] 就假定它是目标上传器。
- 如实选择 gameplay/gamemenu 等类别。优先展示真实游玩，菜单不能改标签冒充战斗。素材数量和类别要求以当前清单为准。

最后验证：刷新后数量、次序、语言映射、远端原尺寸图片加载及商店预览。保留本地成品；认证浏览器日志、会话参数、后台保密截图不进公开 Git。

## 视频

中英文视频需要各自真实界面，不是仅换字幕。锁定同一版本；无 UI 遮挡、鼠标可可靠控制后再录制。保留剪辑表、分辨率、帧率、时长与音轨事实，不能把后配音乐写成原生实录音轨。

上传后检查 Steam 转码和实际播放。独立入口失败不一定代表视频不可用，可核对目标语言商店预览；反之，上传列表存在不等于能够播放。发布字幕、语言或音频支持标记时使用真实能力。

参考：[商店图像](https://partner.steamgames.com/doc/store/assets/standard)、[宣传片](https://partner.steamgames.com/doc/store/trailer)。本 Skill 不把本项目 30 秒宣传片长度当成 Steam 通用要求。
