# 包体交付与审核

## 原生构建

沿用项目引擎和已验证的工具链。Windows 构建需要的微软工具、SDK 和运行库先盘点；安装授权由实际系统流程完成。安装返回需重启不等于安装失败，也不自动替用户重启。

Steamworks SDK 由合法开发者渠道取得，头文件、库和运行时 DLL 架构一致。只分发 SDK 许可允许的运行时组件，不把整份 SDK 放进公开 Git 仓库。开发用 steam_appid.txt 不进入商店发布包；本地桥接日志、凭据、玩家存档也排除。

本项目验证过 Creator 3.8.7 的独立生成工程及 Windows x64 输出。脚本可能使用引擎特有成功退出码；应以当前构建工具约定、目标文件与日志交叉判断，不能一概将非零当失败或只见 exe 就当构建完成。

## 上传到可审核版本

测试计时包只修改生成副本，不开启会连带改变其他数值的总测试开关。测试与正式包分别命名、分别存档；加速养成进度不读写正式Cloud、成就或天梯。核对所有品质、主角加成、完成边界与保存读回，以及编译包内常量，防止只改源码未进包。测试包不得混进正式分支上传清单。

1. 固定可运行目录，记录版本/构建时间、文件数、大小和 SHA256。确认 exe、Resources 和所需运行库齐全。
2. 使用项目已配好的 SteamPipe 流程；若采用后台 ZIP 上传，确认 ZIP 根目录直接含启动文件，不多包一层目录。
3. 大包进度停滞先核对服务器已有上传会话与已接收字节，不重复创建包。优先受支持的 SteamPipe；恢复浏览器分片只能使用当前授权页面已给出的上传信息，不猜接口，不输出令牌。
4. 上传完成后读取 Depot、Manifest、BuildID。确认目标分支实际指向新 Build；上传成功不会自动更新默认分支。
5. 从 Steam 桌面客户端安装和启动。网页 Steamworks 登录与桌面账号不同，开发账号需要真实的应用访问许可；不能以已登录网页推断可在库中安装。
6. 对比 Steam 安装文件和上传包，走新档、保存退出与继续游戏；检查新产生的日志。旧日志没有错误不能证明新包正常。

## 审核与发布边界

按后台当前清单完成启动项、运行库、支持平台、游玩时长和实机检查。本项目提交页要求通过 Steam 游玩至少五分钟、另一台非开发电脑安装运行；后一项由用户实际测试后确认，不能用本机自动检查代替。

分别记录：商店已送审、包体已送审、Valve 已批准、分支已更新、游戏已发行。申请审核后刷新确认进入队列；新包可继续上传，但不要无授权重复提审或发行游戏。

应用元数据发布用于让成就、Cloud 配额等配置生效，和商店素材发布、正式发行不是同一个动作。发布前查差异，避免把其他人的待发布修改一起推出。

参考：[构建上传](https://partner.steamgames.com/doc/sdk/uploading)、[审核流程](https://partner.steamgames.com/doc/store/Review_Process)、[发行流程](https://partner.steamgames.com/doc/store/releasing)。期限与审核清单会变化，执行时核对官方后台。
